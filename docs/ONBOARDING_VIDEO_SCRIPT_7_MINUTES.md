# 온보딩 영상 스크립트 (7분)

`[운영진]` 화면 녹화용. 대괄호는 화면에 보여줄 것, 인용은 말할 것입니다.

---

## 0:00–0:40 — 무엇을 만드는가

[슬라이드: 키오스크 앞에서 망설이는 사람]

> "이 대회에서 여러분이 만드는 것은 키오스크가 아닙니다.
> 이미 있는 키오스크를, 사용자에게 맞게 대신 조작해 주는 서비스입니다.
>
> 여러분은 사용자에게서 필요한 정보를 받아 무엇을 어떤 순서로 누를지 계획을 만들고,
> KioBridge 가 그 계획을 가상 키오스크에서 실행해 검증합니다."

## 0:40–1:20 — 압축 해제와 첫 파일

[탐색기: ZIP 우클릭 → 압축 해제]

> "받은 ZIP 하나만 풀면 됩니다. 경로에 한글이나 공백이 있어도 괜찮습니다."

[폴더가 열리고 `00_START_HERE.html` 이 맨 위]

> "폴더를 열면 `00_START_HERE.html` 이 가장 위에 있습니다. 더블클릭하세요.
> 인터넷 연결이 없어도 열립니다."

## 1:20–2:10 — START HERE 둘러보기

[브라우저: 페이지 상단의 경고 상자 클로즈업]

> "가장 먼저 이 문장을 보세요. **처음에는 두 곳만 보면 됩니다.**
> `00_START_HERE` 와 `participant-workspace`.
> `packages`, `apps`, `environments`, `schemas` 는 플랫폼이 실행에 쓰는 파일이라
> 지금 열 필요가 없습니다."

[스크롤: 다섯 가지 질문 표 → 권장 경로 11단계]

> "이 페이지 하나에 다섯 가지 답이 다 있습니다.
> 무엇을 만드나, 어느 파일을 고치나, 어떤 순서로, 어떻게 확인하나, 무엇을 제출하나.
> 아래 체크박스는 브라우저에 저장되니 진행하면서 체크하세요."

## 2:10–2:50 — 서버 켜기

[탐색기: `start-macos.command` 더블클릭 / Windows 는 `start-windows.bat`]

> "운영체제에 맞는 시작파일을 더블클릭하세요.
> 처음 한 번은 의존성 설치 때문에 조금 걸립니다."

[브라우저에 환경 선택 화면]

> "이 화면이 뜨면 준비 완료입니다. Web 은 3000, API 는 4000 포트입니다."

## 2:50–3:40 — doctor

[터미널: `npm run participant:doctor`]

> "먼저 doctor 를 돌리세요. Node 버전, 서버 상태, 제품 버전,
> 그리고 공식 파일이 그대로인지까지 한 번에 봅니다."

[`[READY] 개발을 시작할 수 있습니다.`]

> "READY 가 나오면 됩니다.
> FAIL 이 있으면 바로 아래에 해결 명령이 같이 나옵니다."

## 3:40–4:40 — demo

[터미널: `npm run participant:demo`]

> "다음은 demo 입니다. 연습용 Sandbox 환경으로 전체 흐름을 한 번 돌립니다."

[출력: 세션 생성 → 제출 → 검증 → SIMULATION PASS]

> "세션을 만들고, 완성된 예제를 제출하고, 검증하고, 가상 키오스크에서 실행하고,
> Evidence 를 받습니다. 이게 여러분 서비스가 하게 될 일의 전체 모습입니다."

[브라우저: 카드가 4개씩 두 페이지, 두 번째 페이지 카드가 자동으로 눌림]

> "여기를 보세요. 후보가 6개라 화면이 두 페이지입니다.
> 그런데 여러분은 페이지 이동 코드를 짜지 않았습니다.
> 후보 ID 만 냈고, KioBridge 가 알아서 페이지를 넘겨 눌렀습니다."

## 4:40–5:30 — 어디를 고치나

[터미널: `npm run participant:init -- --team TEAM-001 --env sandbox`]

> "이제 내 작업폴더를 만듭니다. 팀 ID 와 환경을 정하면 됩니다."

[출력: `다음 파일부터 수정하세요: workspace/TEAM-001/src/participant.ts`]

[에디터: participant.ts 를 열고 STEP 1 주석 클로즈업]

> "여기가 시작점입니다. 함수 아홉 개가 있고 전부 비어 있습니다.
> 각 함수 위 주석에 목적, 입력, 반환, 반드시 할 것, 하면 안 되는 것,
> 그리고 어떤 오류가 나는지가 적혀 있습니다."

[스크롤: STEP 9 의 금지 목록]

> "특히 금지 항목을 보세요. 결제 Action 은 계획에 넣기만 해도 실패합니다."

## 5:30–6:15 — 진행과 검증

[터미널: `npm run participant:progress`]

> "구현하면서 progress 로 확인하세요. 문자열을 찾는 게 아니라
> 실제로 함수를 호출해 보고 판정합니다."

[출력: DONE / NOT_IMPLEMENTED 목록 + MANUAL REVIEW 항목]

> "아래 MANUAL REVIEW 는 기계가 판단할 수 없는 것들입니다.
> 추천 이유가 이해되는지, 키보드만으로 쓸 수 있는지 — 직접 확인하세요."

[터미널: `npm run participant:validate -- --file … --execute`]

> "완성되면 validate 로 검증합니다.
> 실패하면 오류 코드와 함께 어느 STEP 을 고쳐야 하는지 알려줍니다."

## 6:15–7:00 — 제출

[터미널: `npm run participant:package -- --team TEAM-001 --file …`]

> "마지막은 package 입니다. 검증을 통과하지 못하면 패키징이 거부됩니다."

[폴더: `submission-output/TEAM-001/` 파일 목록]

> "제출 폴더가 통째로 만들어집니다. 검증 보고서와 SHA-256 까지 들어 있습니다.
> README 의 빈칸만 채워서 내시면 됩니다."

[슬라이드: 마무리]

> "마지막으로 하나만 기억하세요.
> 공식 판정은 운영진이 깨끗한 패키지에서 여러분의 제출 JSON 을 다시 실행한 결과입니다.
> 그리고 SIMULATION PASS 는 형식과 안전을 통과했다는 뜻이지,
> 좋은 추천이라는 뜻이 아닙니다. 그건 심사에서 봅니다.
>
> 막히면 `docs/ERROR_CATALOG.md` 부터 보세요. 행운을 빕니다."

# 참가팀 아이디어 카탈로그

`[참고]` **여기 있는 것은 정답이 아니라 방향입니다.** 그대로 따라 할 필요도, 전부 만들 필요도 없습니다.

> 참가팀은 키오스크 자체를 다시 만드는 팀이 아닙니다.
> 사용자가 키오스크 앞에서 겪는 정보 입력·탐색·이해·선택의 어려움을 줄이는
> **사용자 접점 서비스**를 만듭니다. 구현 방식은 자유입니다.

각 아이디어는 다음 형식으로 적혀 있습니다.

**문제** → **구현 방식** → **Contract 연결 위치** → **개인정보 주의** → **평가 강점** → **실패 시 대응**

---

## 시작 · 접근

### 1. QR 즉시 시작
**문제** 앱을 깔고 가입해야 쓸 수 있으면 줄 서서 못 씁니다.
**구현** 키오스크에 붙은 QR → 모바일 웹 즉시 실행. 설치·가입 없음.
**Contract** QR 은 `environmentId` 만 알려줍니다. Submission 에는 들어가지 않습니다.
**개인정보** QR 에 이름·연락처를 넣지 마세요. 환경 ID·버전·일회용 nonce 만.
**강점** 첫 화면까지 걸리는 시간이 가장 짧습니다.
**실패 시** QR 을 못 읽으면 환경 목록에서 직접 고르게 하세요.

### 2. 무로그인 익명 세션
**문제** 회원가입 자체가 진입장벽입니다.
**구현** 아무 정보 없이 시작. 필요한 것만 그때그때 물어봅니다.
**Contract** `profile.consent.retentionPolicy: "SESSION_ONLY"`
**개인정보** 저장하지 않는 것이 기본값이어야 합니다.
**강점** 공용 기기에서도 안전합니다.
**실패 시** 해당 없음 — 이것이 fallback 입니다.

### 3. 기기 내 접근성 프로필
**문제** 매번 "큰 글씨" 를 다시 켜야 합니다.
**구현** `localStorage` 또는 앱 Secure Storage 에 접근성 설정만 저장.
**Contract** `profile.accessibility.*`
**개인정보** 접근성 설정만. 이름·연락처는 저장하지 마세요. 삭제 버튼 필수.
**강점** 두 번째 이용부터 눈에 띄게 빨라집니다.
**실패 시** 저장소가 막히면 매번 묻되, 흐름은 그대로 진행하세요.
→ [무로그인 QR 프로필 가이드](LOGINLESS_QR_PROFILE_GUIDE.md)

### 4. PWA
**문제** 매번 URL 을 찾아 들어가야 합니다.
**구현** 홈 화면에 추가. 오프라인 캐시로 재방문이 빠릅니다.
**Contract** 변화 없음 — 전달 방식만 바뀝니다.
**개인정보** 캐시에 개인정보를 남기지 마세요.
**강점** 설치 부담 없이 앱처럼 씁니다.
**실패 시** 브라우저가 PWA 를 지원하지 않아도 일반 웹으로 동작해야 합니다.

## 입력 채널

### 5. 음성 주문
**문제** 화면 글씨가 안 보이거나 터치가 어렵습니다.
**구현** Web Speech API 또는 앱 음성 인식으로 조건을 받습니다.
**Contract** `profile.interaction.preferredInput: "VOICE"`, `fieldMetadata[].source: "VOICE"`
**개인정보** 음성 원본을 서버에 저장하지 마세요. 인식 결과만 씁니다.
**강점** 손과 시야를 쓰기 어려운 사용자에게 직접적입니다.
**실패 시** 인식이 안 되면 터치 입력으로 자연스럽게 넘어가야 합니다.

### 6. 음성 읽어주기
**문제** 추천 이유를 읽기 어렵습니다.
**구현** 화면 내용을 소리로 안내합니다.
**Contract** `profile.accessibility.visualGuidance` 등
**개인정보** 공공장소에서 민감한 내용을 읽지 않도록 주의하세요.
**강점** 저시력 사용자에게 유용합니다.
**실패 시** 음성 API 가 없어도 화면만으로 전체 흐름이 되어야 합니다.

### 7. 보호자 모드
**문제** 본인이 직접 입력하기 어려운 경우가 있습니다.
**구현** 보호자가 대신 입력하되, 화면에 "대리 입력" 임을 표시합니다.
**Contract** `sessionContext.facts.guardianPresent` (병원), `fieldMetadata[].confirmedByUser`
**개인정보** 대리 입력임을 기록하고, 본인 확인 절차를 대체하지 마세요.
**강점** 실제 현장에서 가장 흔한 상황 중 하나입니다.
**실패 시** 보호자가 없으면 직원 도움 경로로 연결하세요.

### 8. 그림·아이콘 중심 선택
**문제** 글자가 많으면 읽기 어렵습니다.
**구현** 사진·아이콘 카드로 고릅니다.
**Contract** 표현 방식일 뿐 Contract 는 그대로입니다.
**개인정보** 해당 없음
**강점** 문해력·언어 장벽을 낮춥니다.
**실패 시** 아이콘에 반드시 텍스트를 병기하세요. 아이콘만으로는 안 됩니다.

### 9. 쉬운 글 변환
**문제** 안내 문구가 행정 용어입니다.
**구현** "쉬운 말 모드" 토글로 문장을 바꿔 보여줍니다.
**Contract** `profile.accessibility.simpleSteps`
**개인정보** 해당 없음
**강점** 관공서 환경에서 특히 효과가 큽니다.
**실패 시** 변환에 실패하면 원문을 보여주되 빈 화면을 만들지 마세요.

### 10. 큰 글씨 · 고대비
**문제** 기본 화면이 작고 흐립니다.
**구현** 토글 두 개. CSS 변수만 바꿔도 충분합니다.
**Contract** `profile.accessibility.largeText`, `highContrast`
**개인정보** 해당 없음
**강점** 가장 적은 노력으로 가장 많은 사용자에게 도움이 됩니다.
**실패 시** 해당 없음

### 11. 카메라 OCR
**문제** 서류 번호를 손으로 옮겨 적기 어렵습니다.
**구현** 카메라로 찍어 필요한 항목만 읽습니다.
**Contract** `fieldMetadata[].source`, `confidence` 를 낮게 잡고 사용자 확인을 받으세요.
**개인정보** **원본 이미지를 저장하거나 전송하지 마세요.** 기기에서 처리하고 버리세요.
**강점** 입력 부담을 크게 줄입니다.
**실패 시** 인식 실패 시 직접 입력으로 넘어가야 합니다. 잘못 읽은 값을 그대로 쓰면 안 됩니다.

### 12. 수어 · 자막
**문제** 음성 안내만으로는 닿지 않는 사용자가 있습니다.
**구현** 안내 영상에 자막을, 가능하면 수어 영상을 함께 제공합니다.
**Contract** `profile.accessibility.hearingSupport`
**개인정보** 해당 없음
**강점** 실제 접근성 요구를 정면으로 다룹니다.
**실패 시** 영상이 없으면 텍스트 안내로 대체하세요.

## 상황 기반 추천

자세한 내용 → [상황 기반 추천 가이드](CONTEXT_AWARE_RECOMMENDATION_GUIDE.md)

### 13. 날씨 기반
**문제** 비 오는 날 서서 기다리기 어렵습니다.
**구현** 날씨 API → 따뜻한 것 / 빨리 받을 수 있는 것을 앞에 둡니다.
**Contract** `sessionContext.extensions["TEAM_X.contextSignals"]`
**개인정보** 정확한 위치를 보내지 마세요. 지역 단위면 충분합니다.
**강점** 이유를 설명하기 쉬운 맥락입니다.
**실패 시** API 실패 시 맥락 없이 추천하고, 이유에서도 언급하지 마세요.

### 14. 계절 · 명절
**문제** 명절에 필요한 것이 평소와 다릅니다.
**구현** 공휴일 API 또는 달력 → 해당 상품·업무를 앞에 둡니다.
**Contract** `contextSignals` `type: "HOLIDAY"`
**개인정보** 해당 없음
**강점** 실제 매장 경험과 잘 맞습니다.
**실패 시** 달력 정보가 없으면 평소 순서로.

### 15. 시간대
**문제** 점심에는 빨리 받고 싶습니다.
**구현** 기기 시계만으로도 됩니다. 외부 API 가 필요 없습니다.
**Contract** `contextSignals` `type: "TIME_OF_DAY"`
**개인정보** 해당 없음
**강점** 실패할 일이 없는 맥락입니다.
**실패 시** 해당 없음

### 16. 재고 · 품절
**문제** 골랐는데 품절이면 처음부터 다시 해야 합니다.
**구현** `fixture.candidates[].available` 을 먼저 걸러냅니다.
**Contract** 후보 필터링 (STEP 4)
**개인정보** 해당 없음
**강점** 가장 흔한 실패를 없앱니다.
**실패 시** 이것은 fixture 에 있으므로 실패할 일이 없습니다.

### 17. 혼잡도
**문제** 지금 줄이 길면 다른 선택을 하고 싶습니다.
**구현** 매장 상태 API 또는 시간대 추정.
**Contract** `contextSignals` `type: "CROWDING"`
**개인정보** 해당 없음
**강점** 대기시간을 실제로 줄여줍니다.
**실패 시** 데이터가 없으면 혼잡도를 언급하지 마세요.

## 반복 이용

### 18. 자주 쓰는 민원 · 최근 선택
**문제** 같은 업무를 매번 처음부터 찾습니다.
**구현** 기기에 저장한 "최근 선택" 을 첫 화면에 보여줍니다.
**Contract** `sessionContext.intent.requestedServiceId`
**개인정보** 업무 종류만 저장하세요. 신청 내용은 저장하지 마세요.
**강점** 재방문 사용자의 시간을 크게 줄입니다.
**실패 시** 저장된 것이 없으면 일반 흐름으로.

## 이해와 통제

자세한 내용 → [설명 가능한 추천 가이드](EXPLAINABLE_RECOMMENDATION_GUIDE.md)

### 19. 대안 비교
**문제** 하나만 보여주면 맞는지 알 수 없습니다.
**구현** 추천 옆에 대안 2~3개를 나란히 보여줍니다.
**Contract** `recommendation.alternativeCandidateIds`
**개인정보** 해당 없음
**강점** 사용자가 스스로 판단할 수 있습니다.
**실패 시** 대안이 없으면 "다른 선택이 없습니다" 라고 명시하세요.

### 20. 추천 거절
**문제** 추천이 마음에 안 들 때 빠져나갈 길이 없습니다.
**구현** "다른 걸 보여주세요" 버튼. 거절한 것은 다시 추천하지 않습니다.
**Contract** `userDecision.decision: "REJECT"` → `executionPlan.actions: []`
**개인정보** 해당 없음
**강점** 사용자 통제감이 크게 올라갑니다.
**실패 시** 남은 후보가 없으면 조건 재입력이나 직원 도움으로 연결하세요.

### 21. 직원 도움
**문제** 어떤 경우는 사람이 필요합니다.
**구현** 어느 화면에서든 누를 수 있는 "직원 도움" 버튼.
**Contract** 환경에 직원 경로 후보가 있으면 그것을, 없으면 화면 안내로.
**개인정보** 해당 없음
**강점** 막다른 길을 없앱니다.
**강조** 병원·관공서에서 UNKNOWN 이 있을 때의 **정답 경로**입니다.
**실패 시** 해당 없음

### 22. 오류 복구
**문제** 잘못 눌렀는데 되돌릴 수 없습니다.
**구현** 각 단계에 "뒤로" 와 "처음부터" 를 둡니다.
**Contract** 해당 없음 — UI 설계 문제입니다.
**개인정보** 해당 없음
**강점** 고령 사용자에게 특히 중요합니다.
**실패 시** 해당 없음

## 개인정보 통제

### 23. 저장정보 삭제
**문제** 저장한 것을 지울 방법이 없으면 저장하기 두렵습니다.
**구현** 설정 화면에 "저장된 설정 지우기" 버튼.
**Contract** 해당 없음
**개인정보** 즉시 지워야 하고, 지웠다고 알려야 합니다.
**강점** 저장 기능을 실제로 쓰게 만드는 조건입니다.
**실패 시** 해당 없음

### 24. 이번 한 번만 사용
**문제** 공용 기기에서 설정이 남으면 곤란합니다.
**구현** 저장 여부를 매번 묻고, **기본값을 "저장 안 함"** 으로 둡니다.
**Contract** `profile.consent.retentionPolicy: "SESSION_ONLY"`
**개인정보** 이것이 안전한 기본값입니다.
**강점** 공용 환경을 실제로 고려했다는 증거입니다.
**실패 시** 해당 없음

## 만들지 말아야 할 것

| 하지 말 것 | 이유 |
| --- | --- |
| 회원가입 강제 | 키오스크의 빠른 순환성과 맞지 않습니다 |
| 증상으로 진료과 추론 | 의료 판단입니다 |
| 법적 자격·지원금 판단 | 행정 판단입니다 |
| 결제·본인확인 완료 Action | 계획에 넣기만 해도 FAIL |
| "AI가 추천했습니다" | 설명이 아닙니다 |
| 확인 없이 자동 실행 | 사용자 통제를 없앱니다 |
| 실제 주민번호·연락처 수집 | `PERSONAL_DATA_NOT_ALLOWED` |

## 로그인·저장·개인정보 정책

| 구분 | 내용 |
| --- | --- |
| Example UI | 로그인 없이 동작하는 **Sandbox 참고 예제**입니다. 공식 정답이 아닙니다. |
| 참가팀 자유 | 로그인, 기기 내 프로필 저장, QR, 음성, 카메라, OCR, 보호자 입력 등을 **선택적으로 자유롭게** 구현할 수 있습니다. |

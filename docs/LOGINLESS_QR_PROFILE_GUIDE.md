# 무로그인 QR 프로필 가이드

`[권장]` 계정 없이 바로 시작하고, 두 번째부터는 빨라지게 만드는 방법.

## "무로그인" 의 정확한 뜻

이 문서에서 말하는 **무로그인**은 로그인 기능을 금지한다는 뜻이 **아닙니다.**

- 로그인 기능을 만드는 것은 **금지되지 않습니다.**
- 계정 없이도 기본 이용이 가능해야 합니다.
- 사용자에게 **즉시 시작 경로**를 제공해야 합니다.
- 로그인은 **선택적 확장 기능**입니다.
- 기기 내 프로필과 서버 계정은 **별개**입니다.
- QR 에는 환경 정보와 일회성 세션 정보만 담습니다.
- QR 에 실제 개인정보를 직접 담는 것은 금지입니다.
- 자동으로 불러온 정보는 사용자에게 다시 보여주고 확인받아야 합니다.

| 방식 | 허용 | 조건 |
| --- | --- | --- |
| 완전 익명 세션 | 허용 | 실제 개인정보 없음 |
| 기기 내 프로필 | 허용 | 최소정보·삭제 기능 |
| 선택적 로그인 | 허용 | 익명 핵심 흐름 유지 |
| 로그인 필수 | 비권장 또는 실패 대상 | 핵심 흐름 차단 |
| QR 개인정보 직접 저장 | 금지 | 민감정보 노출 위험 |

해커톤·심사·시뮬레이션에서는 실제 개인정보가 아닌 **가상·합성 데이터**를 사용하세요.
실제 서비스로 확장할 때는 개인정보 수집 동의, 최소수집, 보관기간, 삭제,
암호화와 접근통제 등 별도 요건을 충족해야 합니다.

## 전체 그림

```
QR 환경정보            (키오스크가 알려주는 것)
  +
기기 내 접근성 프로필   (사용자 휴대폰에만 있는 것)
  +
이번 이용 SessionContext (지금 물어본 것)
  =
ParticipantSubmission
```

세 조각이 **각각 다른 곳**에 있다는 점이 핵심입니다.
서버에 사용자 계정을 만들지 않아도 개인화가 됩니다.

## 1. QR 에는 무엇을 넣나

**환경 정보만** 넣습니다.

```json
{
  "environmentId": "sandbox",
  "fixtureVersion": "1.0.0",
  "sessionNonce": "DEMO-ONLY"
}
```

| 넣어도 됨 | 넣지 말 것 |
| --- | --- |
| 환경 ID | 이름 |
| fixture 버전 | 연락처 |
| 일회용 nonce | 주민등록번호 |
| 매장·창구 번호 | 결제 정보 |
| | 접근성 프로필 원본 |

**QR 은 누구나 찍을 수 있습니다.** 키오스크에 붙어 있고, 사진으로도 남습니다.
개인정보를 넣으면 그 순간 공개됩니다.

프로필을 QR 로 옮기고 싶다면 원시값이 아니라 **사용자 기기에서 만든 임시 토큰**을 쓰고,
그 토큰으로 기기 저장소를 여는 구조를 설계하세요.

## 2. 기기에는 무엇을 저장하나

**접근성 설정만** 저장하는 것을 권장합니다.

```json
{
  "largeText": true,
  "highContrast": false,
  "simpleSteps": true,
  "voice": false,
  "savedAt": "2026-08-03T00:11:00Z"
}
```

이름·연락처·결제정보는 **애초에 받지 마세요.** 받지 않으면 지킬 일도 없습니다.

### 저장소 선택

| 방식 | 적합한 경우 | 주의 |
| --- | --- | --- |
| `localStorage` | 설정 몇 개, 동기 접근 | 5MB 안팎, 문자열만, 브라우저 지우면 사라짐 |
| `IndexedDB` | 구조화된 데이터, 용량 큼 | 비동기, 코드가 길어짐 |
| 앱 Secure Storage | 네이티브 앱 | 기기 잠금과 연동 가능 |
| 쿠키 | **권장하지 않음** | 요청마다 서버로 전송됨 |

이 대회 범위에서는 `localStorage` 로 충분합니다.

## 3. 지켜야 할 여덟 가지

1. **로그인하지 않아도 핵심 기능을 사용할 수 있어야 합니다.** (로그인 기능 자체는 선택사항입니다)
2. 로그인이 있더라도 **선택사항**이어야 합니다.
3. 실제 개인정보 없이 데모가 가능해야 합니다.
4. 저장된 정보를 **조회·수정·삭제**할 수 있어야 합니다.
5. 사용자가 **"이번 한 번만"** 을 고를 수 있어야 하고, 그것이 **기본값**이어야 합니다.
6. QR 에 원시 민감정보를 넣지 않습니다.
7. 저장 정보는 KioBridge 에 필요한 **최소 범위**만 씁니다.
8. 자동으로 불러온 정보는 **화면에 보여주고 확인**받습니다.

### 8번이 특히 중요한 이유

저장된 설정을 조용히 적용하면, 사용자는 자기가 무엇을 켜 놓았는지 모른 채 진행하게 됩니다.
공용 기기라면 **앞사람의 설정**일 수도 있습니다.

```
저장된 설정 불러오기 → 화면에 표시 → "이대로 쓸까요?" → 진행
```

## 4. 공용 기기

매장 태블릿처럼 여러 사람이 쓰는 기기에서는 **저장하지 않는 것이 맞습니다.**

- 기본값을 "저장 안 함" 으로
- "이 기기는 내 것이 아닙니다" 선택지 제공
- 세션이 끝나면 화면 상태 초기화

## 5. 만료

저장한 설정에 `savedAt` 을 남기고, 오래되면 다시 물어보세요.

```
저장 후 90일 → "예전에 저장한 설정입니다. 지금도 맞나요?"
```

## 6. 삭제

한 번의 조작으로 지울 수 있어야 하고, 지웠다고 **알려줘야** 합니다.

```
[저장된 설정 지우기]  →  "이 기기에 저장된 설정을 지웠습니다."
```

## 7. Contract 연결

| 사용자 선택 | Canonical 값 |
| --- | --- |
| 이번만 사용 | `consent.retentionPolicy: "SESSION_ONLY"` · `personalization: false` |
| 기기에 저장 | `consent.retentionPolicy: "UNTIL_USER_DELETES"` · `personalization: true` |
| 저장 안 함 (서버에도 안 보냄) | `consent.retentionPolicy: "NOT_STORED"` |

접근성 설정은 그대로 `profile.accessibility.*` 로 들어갑니다.

## 8. 보안에 대해 솔직하게

이 대회에서 만드는 것은 **데모**입니다. 다음을 구분해서 말하세요.

| 데모 수준 (지금 만드는 것) | 실제 서비스에 필요한 것 |
| --- | --- |
| `localStorage` 평문 저장 | 기기 잠금 연동 암호화 저장소 |
| 일회용 nonce 문자열 | 서명·만료 검증이 있는 토큰 |
| 사용자에게 저장 여부 묻기 | 개인정보 처리방침·동의 이력 관리 |
| 삭제 버튼 | 삭제 요청 처리 절차와 로그 |

**"암호화했습니다" 라고 말하려면 실제로 암호화해야 합니다.**
구현하지 않은 보안을 문서에 적지 마세요. 설계 의도로 적으세요.

# 설명 가능한 추천 가이드

`[필수]` 추천 결과만 보여주지 마세요. **왜 그런지** 함께 보여줘야 합니다.

## 왜 중요한가

키오스크 앞에서 추천을 받은 사람은 두 가지가 궁금합니다.

1. 이게 나한테 맞나?
2. 다른 건 없나?

이유를 보여주지 않으면 사용자는 확인할 방법이 없고, 결국 처음부터 다시 고르게 됩니다.
설명은 친절함이 아니라 **기능**입니다.

## 추천 화면 최소 구성

| 항목 | 없으면 생기는 일 |
| --- | --- |
| 무엇을 추천했는가 | — |
| **왜 추천했는가** | 사용자가 맞는지 판단 못 함 |
| 어떤 사용자 정보를 썼는가 | 잘못 입력한 값을 못 찾음 |
| 어떤 상황정보를 썼는가 | 순서가 이상해 보임 |
| 무엇을 제외했는가 | "왜 그건 없죠?" |
| 대안은 무엇인가 | 마음에 안 들면 막다른 길 |
| 수정할 수 있는가 | 조건을 잘못 넣으면 되돌릴 수 없음 |
| 거절할 수 있는가 | 통제감 상실 |
| 직원 도움 | 막다른 길 |

## 이유 분류

이유마다 어떤 종류인지 태그를 붙이면 화면에서 묶어 보여주기 좋습니다.

| 분류 | 언제 | 예 |
| --- | --- | --- |
| `USER_PREFERENCE` | 사용자가 고른 선호 | "포장을 원하셔서" |
| `ACCESSIBILITY` | 접근성 설정 | "큰 글씨를 쓰고 계셔서 단계를 줄였습니다" |
| `CONTEXT` | 외부 상황 | "지금 비가 내려" |
| `SAFETY` | 제약 조건 | "알레르기와 겹쳐서 제외했습니다" |
| `AVAILABILITY` | 재고·이용 가능 | "지금 준비되지 않아 제외했습니다" |
| `SPEED` | 대기시간 | "빨리 받으실 수 있어서" |
| `USER_HISTORY` | 저장된 이전 선택 | "지난번에 고르셨던 것입니다" |
| `MANUAL_SELECTION` | 사용자가 직접 고름 | "직접 고르신 항목입니다" |

## 좋은 설명과 나쁜 설명

| 나쁨 | 왜 나쁜가 | 좋음 |
| --- | --- | --- |
| "AI가 추천했습니다." | 이유가 없음 | "포장을 선호하셔서 포장 가능한 메뉴를 먼저 보여드립니다." |
| "최적의 선택입니다." | 무엇 기준인지 모름 | "고르신 예산 안에서 가장 빨리 나오는 메뉴입니다." |
| "시스템이 결정했습니다." | 책임 회피 | "등록하신 알레르기와 겹치는 메뉴는 제외했습니다." |
| "회원님께 딱 맞습니다." | 근거 없음 | "큰 글씨를 쓰고 계셔서 선택 단계가 적은 쪽을 앞에 두었습니다." |
| "인기 상품입니다." | 사용자와 무관 | "지금 붐벼서 빨리 받으실 수 있는 것을 먼저 안내드립니다." |

### 문장을 쓰는 법

```
[무엇을 근거로] + [무엇을 했는지]
```

- "**포장을 선호하셔서**(근거) **포장 가능한 메뉴를 먼저 보여드립니다**(행동)."
- "**지금 비가 내려**(근거) **따뜻한 메뉴를 앞에 두었습니다**(행동)."

행동을 단정적으로 쓰지 마세요. "먼저 보여드립니다" 는 되지만
"이것을 드셔야 합니다" 는 안 됩니다.

## 병원·관공서에서 금지되는 표현

| 금지 | 이유 |
| --- | --- |
| "증상을 보니 내과입니다" | 의료 판단 |
| "이 검사가 필요합니다" | 의료 판단 |
| "지원금을 받으실 수 있습니다" | 법률·행정 판단 |
| "자격이 됩니다 / 안 됩니다" | 법률·행정 판단 |
| "접수가 완료되었습니다" | 실제 처리를 하지 않았습니다 |

허용되는 표현:

- "재진이라고 알려주셔서 재진 접수를 안내드립니다."
- "신분증만 쓰실 수 있다고 하셔서 신분증으로 가능한 업무를 보여드립니다."
- "진료과를 모르신다고 하셔서 안내 창구를 먼저 보여드립니다."

## Contract 연결

```json
{
  "recommendation": {
    "recommendedCandidateId": "...",
    "recommendationReasons": [
      "포장을 선호하셔서 포장 가능한 메뉴를 먼저 보여드립니다.",
      "등록하신 알레르기와 겹치는 메뉴는 제외했습니다."
    ],
    "alternativeCandidateIds": ["...", "..."],
    "excludedCandidates": [
      { "candidateId": "...", "reason": "등록하신 알레르기와 겹칩니다" }
    ],
    "unmetConditions": [],
    "confidence": 0.9,
    "requiresReconfirmation": false
  }
}
```

`recommendationReasons` 는 **최소 1개**여야 합니다.
`participant:progress` 가 이를 확인합니다.

외부 맥락을 썼다면 **최소 한 개의 이유가 그 맥락을 설명**해야 합니다.

## 흐름 — 확인 없이 실행하지 않기

```
추천 생성
  → 이유 표시
  → 대안 표시
  → 사용자 수정 가능
  → 사용자 최종 확인       ← 여기를 지나야
  → userDecision
  → executionPlan 생성      ← 계획이 만들어집니다
```

`userDecision.approved !== true` 인데 `executionPlan.actions` 가 비어 있지 않으면
`ACTIONS_WITHOUT_APPROVAL` 로 거부됩니다.

## 확인 화면에 넣을 것

- 무엇을 하려는지 한 문장
- 사용자가 고른 값들
- 금액이 있으면 총액
- **되돌아가는 버튼**
- 이 단계에서 실제 처리가 일어나지 않는다는 안내

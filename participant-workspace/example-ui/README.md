# 사용자 접점 예제 UI

이 폴더는 **Sandbox 참고 UI** 입니다. 로그인 없이 동작하는 하나의 구현 예시이며,
**공식 정답이나 필수 디자인이 아닙니다.** 참가팀은 자유롭게 교체하거나 처음부터 새로 만들 수 있습니다.

이 UI 의 무로그인 동작은 하나의 구현 예시이며,
참가팀이 로그인 기능을 만드는 것을 금지하지 않습니다.

다만 로그인하지 않은 사용자도 핵심 기능을 이용할 수 있어야 합니다.

| 항목 | Example UI | 참가팀 구현 |
| --- | --- | --- |
| 로그인 | 사용하지 않음 | 선택사항 |
| 익명 시작 | 지원 | 핵심 흐름에서 권장·요구 |
| 기기 저장 | 선택 가능 | 자유 |
| QR | Mock 환경정보 | 자유 |
| 실제 개인정보 | 사용하지 않음 | 심사에서는 금지 |
| 사용자 접점 | 웹 예제 | 웹·앱·음성 등 자유 |
| 공식 정답 | 아님 | 참가팀이 직접 구현 |

기기 내 저장은 **선택사항**입니다. 저장하지 않아도 전체 흐름을 이용할 수 있고,
저장되는 것은 접근성 설정과 최소한의 선호뿐이며 언제든 지울 수 있습니다.
웹, 앱, QR, 음성, 카메라, 기기 내 저장, 선택적 로그인 등 사용자 접점 방식은 자유입니다.

해커톤·심사·시뮬레이션에서는 실제 이름·전화번호·주민등록번호·환자번호·차량번호·주소 등
실제 개인정보를 사용하지 마세요. 테스트에는 **가상·합성 데이터**를 사용합니다.

실제 서비스로 확장할 때는 개인정보 수집 동의, 최소수집, 보관기간, 삭제,
암호화와 접근통제 등 별도 요건을 충족해야 합니다.

## 실행 방법

`index.html` 을 더블클릭해도 화면은 열리지만, 브라우저에 따라 `file://` 에서는
로컬 파일 읽기(fetch)나 일부 저장 동작이 막힐 수 있습니다.
아래처럼 **로컬 HTTP 서버**로 여는 방식을 권장합니다.

```bash
cd participant-workspace/example-ui
python3 -m http.server 8088
```

그다음 <http://127.0.0.1:8088/> 을 엽니다.

| 방식 | 화면 | Mock 파일 읽기 | 공식 시뮬레이터 연동 |
| --- | --- | --- | --- |
| `file://` 직접 열기 | 동작 | 브라우저에 따라 막힘 | 서버가 켜져 있으면 동작 |
| `python3 -m http.server 8088` | 동작 | 동작 | 서버가 켜져 있으면 동작 |

공식 개발 서버(`npm run dev`) 를 함께 켜면 실제 Sandbox 검증 결과를 볼 수 있고,
꺼져 있으면 **독립 미리보기 모드**로 표시됩니다. 가짜 PASS 를 만들지 않습니다.


`[참고]` **이 화면은 참고 예제입니다. 자유롭게 교체하거나 처음부터 다시 만드세요.**

## 과제의 핵심

> 참가팀은 키오스크 자체를 다시 만드는 팀이 아닙니다.
>
> 사용자가 키오스크 앞에서 겪는 정보 입력, 탐색, 이해, 선택의 어려움을 줄이는
> **사용자 접점 서비스**를 만듭니다.
>
> 웹, 앱, PWA, QR, 음성, 카메라, OCR, 보호자 입력, 기기 내 저장, 외부 API 등
> 구현 방식은 자유입니다.
>
> 최종 결과가 KioBridge Canonical Contract에 맞는 ParticipantSubmission으로 변환되고,
> 사용자가 확인한 Semantic ExecutionPlan이 공식 시뮬레이터에서 안전하게 동작하면 됩니다.

## 여는 법

브라우저에서 `index.html` 을 **더블클릭**하세요. 서버도, 빌드도, 인터넷도 필요 없습니다.

```
participant-workspace/example-ui/index.html
```

| --- | --- | --- |
| 화면만 확인 | `LOCAL UI PREVIEW ONLY` | 서버 없이 열었을 때 |
| 실제 검증 | `SIMULATION SERVER RESULT` | `npm run dev` 로 서버를 켠 뒤 "서버로 보내기" |

## 이 예제가 보여주는 것

| 흐름 | 무엇을 보여주나 |
| --- | --- |
| 1. 이번만 사용하기 | 계정 없이 바로 시작 (이번 이용은 저장하지 않음) |
| 2. 화면 설정 | 큰 글씨 · 고대비 · 쉬운 단계 · 음성 안내 |
| 저장 선택 | "이번만 사용" vs "이 기기에 저장" · 지우기 버튼 |
| 3. 예시 QR | 환경 ID·버전·일회용 값만 — 개인정보 없음 |
| 4. 이번 이용 | 크기 선택 + 오늘 상황 카드 |
| 5. 추천 | 결과 · **왜 골랐는지** · 사용한 정보 · 제외한 것 · 대안 |
| 거절 / 바꾸기 / 다시 / 직원 도움 | 사용자가 통제 |
| 6. 최종 확인 | **확인 전에는 실행계획을 만들지 않습니다** |
| 7. 결과 | Canonical Submission · Semantic Plan 미리보기 · JSON 내려받기 |

## 저장하는 것 / 하지 않는 것

**저장:** 접근성 설정 4개 (큰 글씨·고대비·쉬운 단계·음성) — `localStorage`, 이 브라우저 안에만.

**저장하지 않음:** 이름·연락처·주민번호·결제정보. 애초에 입력받지 않습니다.

사용자는 언제든 "저장된 설정 지우기" 를 누를 수 있고, 기본값은 "저장하지 않음" 입니다.
자동으로 불러온 설정도 화면에 보여주고 확인을 받습니다.

## 접근성

`lang="ko"` · skip link · 모든 입력에 label · 버튼 accessible name ·
`aria-live` 로 결과·오류 안내 · 키보드만으로 전체 이용 · `:focus-visible` ·
최소 44px 클릭 영역 · 큰 글씨/고대비 토글 · `prefers-reduced-motion` 대응 ·
상태를 색만으로 구분하지 않음 (테두리·문구 병기).

음성 안내는 브라우저가 지원할 때만 켜지며, **없어도 전체 흐름이 동작합니다.**

## 추천 규칙

간단하지만 **설명 가능한** 규칙입니다. 참가팀은 훨씬 정교하게 만들어도 됩니다.

1. 품절·거절한 항목 제외
2. 고른 크기를 지원하지 않으면 제외
3. 큰 글씨/쉬운 단계를 쓰면 단순한 쪽을 앞으로
4. 점심·혼잡이면 빠른 쪽을 앞으로
5. 비가 오면 오래 머물지 않아도 되는 쪽을 앞으로

이유는 항상 사람의 말로 씁니다. `AI가 추천했습니다` 같은 문장은 쓰지 않습니다.

## 상황 정보

`mock-context.json` 을 읽되 **실패해도 화면이 멈추지 않습니다.**
실제 서비스라면 날씨·혼잡도 API 를 부르고 timeout·fallback·캐시를 두세요
→ [외부 API 안전 가이드](../../docs/EXTERNAL_API_SAFETY_GUIDE.md)

상황 정보는 Core 계약을 건드리지 않고 팀 namespace 로만 들어갑니다:

```json
"extensions": { "TEAM_EXAMPLE.contextSignals": [ … ] }
```

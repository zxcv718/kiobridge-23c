KioBridge Simulation Kit — 참가팀 시작 안내

이 페이지는 인터넷 없이 열립니다. 링크는 모두 이 폴더 안의 파일입니다.

제품 버전 5.1.4 inputContractVersion 1.0.0 Web 3000 · API 4000
참가팀은 키오스크 자체를 다시 만드는 팀이 아닙니다. 사용자가 키오스크 앞에서 겪는 정보 입력·탐색·이해·선택의 어려움을 줄이는 사용자 접점 서비스를 만듭니다. 웹·앱·PWA·QR·음성·카메라·보호자 입력·기기 내 저장·외부 API 등 구현 방식은 자유입니다.

처음에는 두 곳만 보세요.
00_START_HERE 와 participant-workspace/ 입니다.
packages, apps, environments, schemas 는 플랫폼이 실행에 쓰는 파일이며 참가팀 구현 시작점이 아닙니다.

참가팀이 답해야 하는 다섯 가지

질문답
무엇을 만드나사용자를 대신해 키오스크를 조작할 의미 기반 실행계획을 만드는 서비스. 키오스크 자체를 새로 만들지 않습니다.
어느 파일을 고치나participant-workspace/src/participant.ts (init 후에는 workspace/<팀ID>/src/participant.ts)
어떤 순서로9개 함수를 위에서부터. participant:progress 가 남은 단계를 알려줍니다.
어떻게 확인하나participant:validate → SIMULATION PASS
무엇을 제출하나participant:package 가 만든 submission-output/<팀ID>/ 폴더

  1. ZIP 압축 해제
  2. 이 페이지(00_START_HERE.html) 열기 — 지금 하고 있습니다
  3. 운영체제에 맞는 시작파일 실행
    macOS start-macos.command · Windows start-windows.bat · Linux start-linux.sh
  4. npm run participant:doctor
  5. npm run participant:demo
  6. npm run participant:init -- --team TEAM-001 --env sandbox
  7. workspace/TEAM-001/src/participant.ts 구현
  8. npm run participant:progress
  9. npm run participant:validate
  10. npm run participant:package
  11. 생성된 submission-output/ 폴더 제출

로그인·저장·개인정보

로그인 기능은 선택사항입니다. 다만 핵심 기능은 로그인 없이도 이용할 수 있어야 합니다.

  • Example UI 는 로그인 없이 동작하는 참고 예제입니다. 공식 정답이 아닙니다.
  • 로그인, 기기 내 저장, QR, 음성, 카메라 등은 자유롭게 구현할 수 있습니다.
  • 해커톤·심사에는 실제 개인정보가 아닌 가상 데이터를 사용하세요.
  • 실제 서비스로 확장할 때는 동의·최소수집·보관기간·삭제·보안 요건을 따로 충족해야 합니다.

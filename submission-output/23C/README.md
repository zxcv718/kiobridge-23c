# 23C 최종 제출

| 항목 | 내용 |
| --- | --- |
| 팀명 | 23C |
| 환경 | `chicken-store` |
| 서비스 한 줄 소개 | 키오스크 앞에서 **눈치 볼 틈과 이유를 없애는** 주문 도우미 — 몇 가지만 여쭤보고 화면을 그 사람에게 맞춘 뒤, 결제 직전까지 대신 눌러 드립니다. |
| 사용자 정보 수집 방식 | 웹 화면 터치가 기본입니다. 로그인이 없고 익명으로 끝까지 갑니다. 보호자·직원이 대신 눌러 주면 «옆에서 도와주기»로 골라 대리 입력(`ASSISTED_INPUT`)으로 기록하고, 이 기기에 저장해 둔 설정을 되살리면 `IMPORTED` 로 기록합니다(자동 적용하지 않고 내용을 보여드린 뒤 확인받습니다). 매장 QR 은 카메라로 **읽기만** 합니다. 음성 입력은 구현하지 않았으므로 선택지에 넣지 않았습니다. |
| 추천 방식 요약 | 알레르기·품절·미지원은 점수를 깎지 않고 **후보에서 아예 제외**한 뒤(STEP 4), 남은 후보를 맵기·형태·이용방식·컵·가격 다섯 축으로 점수 매겨 1위를 뽑습니다. 알레르기를 «잘 모르겠어요»로 답하면 임의로 판단하지 않고 재확인을 요구하며, 두 번째에도 확실해지지 않으면 안전 중단 화면으로 갑니다. **조건에 맞는 메뉴가 하나도 없으면 추천을 만들지 않고**(`recommendedCandidateId: null`) 왜 못 찾았는지를 사실로 말합니다. 상황 신호(시간대)는 기기 시계로만 만들어 **정렬 순서만** 바꾸고 후보를 제외하지 않으며, 이용 방식을 직접 고른 경우에는 개입하지 않습니다. 외부 API 를 쓰지 않습니다. |
| 접근성 고려사항 | 선언한 채널 8종이 전부 화면에서 실제로 동작하며, 그 사실을 자기 선언이 아니라 **테스트가 소스·CSS 를 읽어 검사**합니다. 누를 수 있는 것은 예외 없이 48px 이상이고(`cursor: pointer` 를 쓴 모든 CSS 규칙을 검사), 아이콘만 있는 버튼을 만들 수 없게 타입이 막으며(«아이콘 단독 금지»는 보이는 글자가 아니라 **접근 가능한 이름**을 뜻합니다), 상태를 색으로만 말하지 않습니다. 색 대비는 눈으로 고르지 않고 계산기(WCAG 2.1 상대 휘도)로 **전수 검사**합니다 — CSS 를 파싱해 `color` 와 `background` 를 같은 규칙에서 선언한 자리를 전부 찾아 기본·고대비 두 팔레트에서 각각 재므로, 색을 새로 넣으면 검사도 저절로 늘어납니다. 다만 색값 자체는 **디자인 토큰 그대로** 쓰며, 그 결과 남는 미달 두 건은 아래 알려진 제한사항 ⑦ 에 수치까지 적었습니다. 키보드만으로 시작부터 최종 확인까지 완주하는 것을 실측하고, 모바일(390×844)에서 가로 넘침이 없는지도 잽니다. |
| 실행 방법 | `npm install` → `npm run start:api` → 다른 터미널에서 `npx vite --config workspace/23C/ui/vite.config.ts` 후 `http://localhost:5173`. 배포본은 `https://kiobridge-23c-demo.vercel.app` 이며 **모바일 화면 기준**으로 만들었습니다. Simulation API 가 없는 환경에서는 실행 대신 주문 계획(JSON) 내려받기로 전환됩니다. 공식 재실행은 이 폴더의 `participant-submission.json` 을 깨끗한 키트에 올려 주세요. |
| 알려진 제한사항 | ① **매장 QR 은 대조까지만 합니다.** 세션을 발급받으려면 서버가 필요하고 그건 참가팀 배포본 범위 밖이라, 읽은 매장 코드를 이 기기가 가진 환경과 맞춰 보는 데서 멈춥니다. ② **화면 안에서의 카메라 스캔은 `BarcodeDetector` 가 있는 브라우저(Chrome·Android)에서만 됩니다.** iOS 는 브라우저 종류와 무관하게 막혀 있어(WebKit 강제) 크롬으로 열어도 같습니다. 그래서 주소에 실려 온 매장 코드(`?env=`)를 읽도록 해 두었습니다 — 폰의 기본 카메라 앱이 QR 을 풀고 그 주소로 열면 화면 안 스캔과 같은 자리에 도착합니다. 매장 코드 직접 입력·직원 요청·건너뛰기도 같은 화면에 함께 있습니다. ③ **기기 간 주문 인계는 없습니다.** ④ 저장은 이 기기(localStorage)에만 하며 서버·계정에는 아무것도 남기지 않습니다. ⑤ 음성 입력·TTS 는 구현하지 않았습니다. ⑥ 결과 화면에서 공식 판정(PASS/stopType)은 **의도적으로 표시하지 않습니다** — 키트 서버만 낼 수 있는 값이라 화면에 임의로 쓰면 가짜 판정이 되기 때문입니다. ⑦ **디자인 토큰을 그대로 쓴 결과 본문 대비 기준(4.5:1) 미달이 두 곳 남습니다** — 보조 글씨색 `#8c8c8c` 는 흰 바탕에서 **3.36:1**, 주 버튼의 브랜드 주황 `#ff5a1f` 위 흰 글씨는 **3.12:1** 입니다. 기획이 «디자인에 있는 것은 디자인 그대로»를 요청해 받아들인 값이고, 숨기지 않기 위해 두 수치를 테스트가 소수점까지 못 박습니다(값이 조용히 더 나빠지면 실패합니다). 대비가 필요한 분께 이 서비스가 드리는 답은 색을 조금 조정하는 것이 아니라 **고대비 화면**이며, 프로필 생성 2/3 에서 한 번의 선택으로 켜집니다 — 고대비 팔레트에는 미달이 **하나도 없도록** 같은 검사가 강제합니다. 참고로 안전 중단 화면의 「ERROR」(디자인 99:1340)에 쓰인 제3의 주황 `#fa520f` 는 **미달이 아닙니다** — 22px Bold 라 WCAG 1.4.3 의 큰 글씨(18.66px 이상 굵게)에 해당해 기준이 3:1 이고, 실측 **3.34:1** 로 넘습니다. 검사가 이 자리의 크기와 굵기를 CSS 에서 직접 읽어 «정말 큰 글씨인지»를 먼저 확인한 뒤 3:1 로 재므로, 나중에 이 글자가 작아지면 그때는 본문 기준으로 판정돼 실패합니다. ⑧ **알레르기 첫 걸음에 「잘 모르겠어요」가 없습니다.** 디자인(99:1228)의 선택지가 「없어요」·「있어요」 둘뿐이라 맞췄습니다. 그 결과 화면에서 하드 제약 «미확인» 상태로 들어가는 입구가 없습니다 — 값과 엔진 동작은 그대로 살아 있어(조합 검증 12,960개에 「모름」 포함) 옛 저장본이나 대리 입력으로 들어오면 여전히 재확인을 요구합니다. ⑨ **직원 도움은 상시 노출이 아닙니다.** 디자인이 직원 도움을 «모든 화면»이 아니라 «필요한 화면»에 두기 때문입니다 — QR 연동(150:329)은 «스캔하기 어려우신가요?» 아래 [직접 입력]과 나란히 **[직원 요청] 버튼**을 두고, 안전 중단(99:1337)은 버튼 대신 「매장 직원에게 말씀해 주세요」라는 **문장**으로 안내합니다. 그 둘뿐이며, 우리도 그대로 따랐습니다. 접근성 설정의 «직원 도움 먼저»를 켜면 그때는 모든 화면 최상단에 고정 노출됩니다. 선언(`staffHelpReachableFromEveryStep`)은 그에 맞춰 `false` 입니다. |

## 이 제출물이 무엇을 보증하고 무엇을 보증하지 않는가

`simulation-evidence.json` 의 `PASS` 는 **계약·안전·상태 전환 검증만** 뜻합니다.
추천 품질·접근성 UX·창의성은 사람이 봐야 하며, 그 판단에 필요한 것을
`MANUAL_REVIEW_CHECKLIST.md` 와 `participant-ux.json` 에 적었습니다.

결제성 동작은 «차단됐다»가 아니라 **애초에 계획에 넣지 않습니다**
(`plannedPaymentActionCount = 0`). 실행 계획은 장바구니 확인(`verify_cart`)에서 끝나며,
결제는 사람이 직접 하도록 남겨 둡니다.

## 화면에서 확인해 보실 것

- **예산 5,000원** 을 고르면 «조건에 맞는 메뉴가 없어요» 로 갑니다. 이 가게 최저가가
  5,500원이라 실제로 살 수 있는 것이 없는 상황이며, 왜 못 찾았는지(품절 1개·예산 초과 7개)를
  숨기지 않고 말한 뒤 조건을 고칠 길을 줍니다.
- 위 예산 조건을 **고치지 않고 다시 추천**을 받으면 안전 중단 전용 화면으로 갑니다.
  첫 번째에는 조건을 고칠 기회를 주고, 두 번째에야 멈춥니다 — 막다른 길을 만들지 않습니다.
- **프로필 생성 1/3 의 «큰 글씨»** 를 고르면 글자가 정확히 1.2배가 됩니다 —
  화면에 적힌 「글자를 20% 크게」와 같은 값이며, 그 둘이 갈라질 수 없게 계산식으로 묶었습니다.
- **프로필 생성 3/3 의 «안내 켜짐»** 을 켜면 다음에 누를 버튼이 테두리와 화살표로
  강조됩니다. 아직 답을 고르지 않아 누를 수 없는 동안에는 가리키지 않습니다 —
  누를 수 없는 버튼을 «다음에 누를 버튼»이라고 알려 주면 안내가 아니라 헛걸음입니다.
- **장바구니 확인** 에서 각 옵션이 어떻게 정해졌는지 구분해 보여줍니다 —
  고르신 값 / «상관없어요»라 이 메뉴의 값으로 정한 값 / 원하신 값이 없어 대체한 값.
- **결과 화면의 «안전 시연»** 에서 공식 오류 7종을 일부러 주입해 안전 엔진이 즉시 멈추는
  것을 볼 수 있습니다(매번 새 세션이라 정상 결과는 보존됩니다).
- **«큰 글씨»를 켜 놓고 아무 화면이나** 보아 주세요. 맵기의 불꽃, 장바구니의 표식 동그라미,
  계산 화면의 큰 제목이 **글자와 같은 비율로 함께 커집니다.** 디자인의 치수(불꽃 30px·
  동그라미 16px)는 본문이 18px 일 때의 값이라 숫자를 그대로 박아 두면 큰 글씨를 켠 분에게서만
  그림이 상대적으로 작아집니다 — 그분은 글씨가 안 보여서 켠 분입니다. 그래서 본문 크기에
  매달았고, 기본 상태에서는 디자인 값 그대로입니다.
- **안전 중단 화면**(예산 5,000원으로 두 번째 추천을 받으면 나옵니다)은 디자인 99:1337 을
  그대로 그렸습니다 — 돋보기 일러스트까지 시안에서 받아 왔습니다. 우리가 덧붙인 「왜
  멈췄나요?」는 접어 두어, 펴기 전 화면이 디자인과 같습니다.

## 항목별 확인 방법

| 항목 | 어떻게 확인했나 |
| --- | --- |
| 로그인 없이 | 로그인 기능 자체가 없습니다. 시작 화면에서 바로 질문으로 들어갑니다. |
| 키보드만으로 | **측정.** Tab/Enter만으로 시작→7문항→추천→최종확인 완주를 자동 테스트로 확인. 가짜 버튼(div+onClick, role="button") 부재도 정적 검사로 확인. |

| 확대 200% | **측정.** 640px 뷰포트 zoom 200%에서 가로 넘침 0px 확인. |
| 색상 없이 | **측정.** 설정 상태가 "켬/끔" 글자와 aria-pressed로 노출되는 것을 확인. 제외 사유는 문장, 결과는 "PASS"/"안전 정지" 글자로 표시합니다. |
| 추천 이유 | **미확인.** 고령 사용자 이해도 테스트를 아직 하지 못했습니다. 문장은 "[근거]+[행동]" 형식이며 "AI가 추천했습니다" 같은 표현을 쓰지 않습니다. |

## 팀 메모

**1. 이 PASS는 자격 요건이지 점수가 아닙니다.** resultScope는 SIMULATION_VALIDATION_ONLY입니다. 판단해 주시길 바라는 것은 추천의 적절성, 이유의 납득 가능성, 접근성 UX입니다.

**2. 안전 시연을 직접 해보실 수 있습니다.** 결과 화면에서 공식 오류 주입 7종(결제 시도 / 승인 없이 실행 / 확인 절차 생략 / 품절 메뉴 / 화면 순서 위반 / 금지 동작 / 미정의 상태)을 눌러 보실 수 있습니다. 주입은 매번 새 세션에서 실행되므로 원래 PASS 결과가 보존됩니다.

**3. 하지 않은 것을 명시합니다.** 음성 입력·QR 시작·날씨/혼잡도 신호·병원/관공서 환경은 구현하지 않았고 화면에도 노출하지 않습니다.

**4. 상황신호의 한계를 밝힙니다.** 시간대 신호는 기기 시계로만 만들며, 붐비는 시간대에 "빨리 나온다"고 말하지 않습니다 — fixture에 조리시간 데이터가 없어 근거가 없기 때문입니다. 말할 수 있는 것은 "자리를 기다리지 않아도 된다"뿐이고 그것만 이유에 적습니다.

**5. 확인하지 못한 것.** 고령 사용자 실사용 테스트와 데모 영상.
